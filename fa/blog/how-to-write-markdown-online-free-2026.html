نحوه نوشتن و پیش‌نمایش Markdown آنلاین به صورت رایگان (راهنمای 2026)

نشانه‌گذاری (Markdown) روشی متن ساده برای نوشتن اسناد قالب‌بندی‌شده است. به جای فشار دادن دکمه‌ای در نوار ابزار برای بولد کردن متن یا تیتر، چند نماد ساده تایپ می‌کنید - علامت هشتگ برای تیتر، ستاره برای بولد کردن - و متن به یک صفحه تمیز و قالب‌بندی شده تبدیل می‌شود. در همه جا استفاده می شود: فایل های README پروژه، اسناد، یادداشت های شخصی، پیش نویس های وبلاگ، پیام های چت و پست های انجمن در GitHub. بهترین بخش این است که می‌توانید Markdown را به صورت آنلاین، بدون نصب چیزی و بدون ایجاد حساب کاربری بنویسید و پیش‌نمایش کنید. در این راهنما شما اصول اولیه را می آموزید، یک سند کامل از ابتدا تا انتها ایجاد می کنید و از اشتباهات رایجی که افراد تازه کار دچار آن می شوند جلوگیری می کنید.

Markdown چیست و چرا مفید است؟

Markdown طوری طراحی شده بود که قبل از تبدیل شدن قابل خواندن باشد. یک فایل Markdown فقط متن است، بنابراین در هر ویرایشگری باز می‌شود، روی هر دستگاهی اجرا می‌شود و هرگز کلمات شما را در یک قالب اختصاصی قفل نمی‌کند. این را با یک سند واژه‌پرداز مقایسه کنید که به نرم‌افزار خاصی نیاز دارد و قالب‌بندی آن پشت منوها پنهان است. با Markdown، هر چه تایپ کنید همان را دریافت می‌کنید و نمادهای قالب‌بندی قابل مشاهده و قابل فهم باقی می‌مانند.

Markdown در این مکان‌ها بهترین عملکرد را دارد:

  • توجه: یادداشت های جلسه، یادداشت های مطالعه و یادداشت های روزانه به سرعت نوشته می شوند و به راحتی یافت می شوند، زیرا محدودیتی در قالب بندی وجود ندارد.
  • اسناد: پروژه های نرم افزاری، راهنمای کاربر و ویکی های داخلی معمولاً در Markdown نوشته می شوند، زیرا به راحتی به صفحات وب تبدیل می شوند.
  • فایل‌های README: هر پروژه در GitHub با یک فایل README.md شروع می شود که توضیح می دهد پروژه چه کاری انجام می دهد و چگونه از آن استفاده کنید.
  • پیش نویس وبلاگ: بسیاری از پلتفرم‌های وبلاگ‌نویسی Markdown را مستقیماً می‌پذیرند، بنابراین می‌توانید پیش‌نویس‌ها را به صورت متن ساده بنویسید و بدون تغییر قالب منتشر کنید.
  • پیام ها و انجمن ها: برنامه‌های چت، ردیاب‌های مشکل و سایت‌های گفتگو اغلب از Markdown برای پررنگ، مورب، پیوندها و کد پشتیبانی می‌کنند.

اگر نوشته شما در نهایت به یک صفحه وب، یک README یا مجموعه ای از یادداشت ها تبدیل شود، Markdown معمولاً سریع ترین مسیر از ایده تا سند نهایی است.

مبانی: سرفصل ها، تاکیدات، لیست ها، لینک ها، تصاویر، کدها و جداول

برای بیشتر نوشته‌های روزمره، شما فقط به تعداد انگشت‌شماری نماد نیاز دارید. در اینجا آنها را به همراه مثال‌هایی که می‌توانید بلافاصله امتحان کنید، آورده‌ایم.

تیترها

از یک تا شش علامت هش استفاده کنید. یک هش بزرگترین عنوان و شش کوچکترین آن است. یک سند باید یک عنوان سطح بالا داشته باشد، سپس بخش‌های زیر آن:

# Main Title
## Section Heading
### Smaller Subheading

تاکید

برای تأکید، متن را داخل ستاره یا زیرخط قرار دهید. یک ستاره آن را ایتالیک و دو ستاره آن را بولد می‌کند:

*italic text* مایل می شود و **bold text** پررنگ، پررنگ می‌شود. از پررنگ کردن به مقدار کم - برای عبارات مهم و هشدارها - و از کج کردن به میزان کم برای تأکید یا عناوین کتاب استفاده کنید.

لیست ها

در لیست‌های نامرتب، بعد از خط تیره، ستاره یا علامت جمع، یک فاصله قرار می‌گیرد. در لیست‌های مرتب، بعد از نقطه، یک عدد قرار می‌گیرد. برای تودرتو کردن آیتم‌ها، آنها را با دو فاصله تورفتگی دهید:

- First item
- Second item
  - Nested item

1. First step
2. Second step
3. Third step

لینک‌ها و تصاویر

متنی که در پیوند ظاهر می شود در داخل کروشه قرار می گیرد و آدرس بلافاصله بعد از آدرس در پرانتز گرد آمده است. تصاویر از همین روش استفاده می کنند، فقط با علامت تعجب در ابتدا:

[Visit Anwaar Digital](https://anwaardigital.com/)
![A descriptive caption](photo.jpg)

همیشه توضیحات معناداری برای تصاویر بنویسید. این به خوانندگان صفحه کمک می‌کند و اگر تصویر بارگذاری نشود، به عنوان متن پشتیبان ظاهر می‌شود.

کد

برای یک قطعه کوتاه در یک جمله، آن را در یک بک تیک قرار دهید، مثلاً `print("hello")`برای بلوک‌های طولانی کد، قبل و بعد از کد، در هر خط از سه علامت برگشت استفاده کنید. همچنین می‌توانید نام زبان را بعد از علامت برگشت اولیه تایپ کنید، که بسیاری از پیش‌نمایش‌دهندگان برای هایلایت کردن سینتکس از آن استفاده می‌کنند:

```python
print("Hello, Markdown!")
```

میز

جداول از علامت‌های پایپ و خط تیره تشکیل شده‌اند که با خط از هم جدا شده‌اند. آنها را کوتاه نگه دارید - خواندن جداول عریض به صورت متن ساده دشوار است:

| Tool | Use |
| --- | --- |
| Markdown Editor | Write and preview |
| Word Counter | Check length |

نقل قول ها و خطوط افقی

یک حرف بزرگ در ابتدای یک خط، یک نقل قول بلوکی ایجاد می‌کند که برای نقل قول از کسی یا تأکید بر یک یادداشت مفید است. سه خط تیره در یک خط، یک خط افقی ایجاد می‌کنند که بخش‌ها را از هم جدا می‌کند:

> This is a quoted line.
---

پیش‌نمایش زنده گردش کار

نوشتن Markdown بدون دیدن آن - تایپ نمادها و امید به اینکه نتیجه درست به نظر برسد - کند و مستعد خطا است. یک گردش کار بهتر استفاده از پیش‌نمایش زنده است: شما در یک طرف تایپ می‌کنید و نتیجه قالب‌بندی شده بلافاصله در طرف دیگر ظاهر می‌شود. ما ویرایشگر Markdown دقیقاً به همین روش کار می‌کند، کاملاً در مرورگر شما، بدون نیاز به ثبت‌نام. وقتی عنوانی را تایپ می‌کنید، به یک عنوان تبدیل می‌شود. وقتی لیست را اصلاح می‌کنید، پیش‌نمایش خود به خود اصلاح می‌شود. شما خطاها را در همان لحظه وقوع متوجه می‌شوید، به جای اینکه آنها را پس از انتشار کشف کنید.

یک گردش کار خوب برای پیش‌نمایش زنده به این شکل است:

  1. در مرورگر شما ویرایشگر Markdown باز کردن
  2. ابتدا ساختار خود را پیش‌نویس کنید: عنوان، سرفصل‌های بخش‌ها و نکات مهم هر بخش.
  3. پاراگراف‌های زیر هر عنوان را پر کنید و هنگام نوشتن، پیش‌نمایش را بررسی کنید.
  4. لینک‌ها، تصاویر و بلوک‌های کد را اضافه کنید و تأیید کنید که هر یک در پیش‌نمایش درست به نظر می‌رسند.
  5. پیش نمایش را از بالا به پایین مانند یک خواننده بخوانید، نه یک نویسنده. قبل از صادرات هر چیزی را که بد به نظر می رسد برطرف کنید.

از آنجا که ویرایشگر کاملاً به صورت بومی در مرورگر شما اجرا می‌شود، پیش‌نویس شما هرگز از دستگاهتان خارج نمی‌شود. این موضوع هنگام نوشتن کارهای منتشر نشده، اسناد داخلی یا هر چیز محرمانه‌ای مهم است - هیچ نسخه‌ای از سرور برای نگرانی وجود ندارد.

نوشتن یک سند از ابتدا تا انتها: یک مثال عملی

فرض کنید باید یک فایل README کوتاه برای پروژه بنویسید. با یک ساختار شروع کنید، سپس آن را پر کنید. یک ساختار قوی شامل موارد زیر است: عنوان، خلاصه یک جمله‌ای، کاری که پروژه انجام می‌دهد، نحوه نصب آن، نحوه استفاده از آن و لینکی به راهنمای بیشتر. این ساختار در Markdown به این شکل است:

# My Project
A short description of what this project does.
## Features
- Feature one
- Feature two
## Installation
1. Download the files.
2. Open the main file.
## Learn More
[Full documentation](https://example.com/docs)

توجه داشته باشید که ساختار را می توان بدون هیچ گونه قالب بندی از قبل خواند. این قدرت اصلی Markdown است: حتی فایل خام نیز قابل درک است. پس از آماده شدن ساختار، هر بخش را یکی یکی گسترش دهید و پیش نمایش کنید. پاراگراف ها را کوتاه نگه دارید، از سرفصل ها برای جدا کردن اسناد طولانی استفاده کنید و دستورالعمل ها را در لیست های شماره گذاری شده قرار دهید تا خوانندگان بتوانند آنها را گام به گام دنبال کنند. پس از تکمیل سند، ما شمارنده کلمات تعداد کلمات از یا ما شمارنده حروف اگر پلتفرم هدف شما دارای محدودیت طول است، تعداد کاراکترها را بررسی کنید.

خروجی گرفتن و کپی کردن HTML

وقتی سند در پیش‌نمایش درست به نظر رسید، معمولاً به فرمت دیگری از آن نیاز دارید. بیشتر ویرایشگرهای Markdown دو خروجی مفید ارائه می‌دهند. اولین راه، کپی کردن خود Markdown خام است که می‌توانید آن را در GitHub، یک برنامه یادداشت‌برداری یا یک پلتفرم وبلاگ‌نویسی که از Markdown پشتیبانی می‌کند، پیست کنید. دومی کپی کردن HTML رندر شده است که می‌توانید آن را در یک سیستم مدیریت محتوا، قالب ایمیل یا صفحه وب جایگذاری کنید. اگر زمانی نیاز دارید که این HTML را به طور ایمن بازرسی یا رمزگذاری کنید - به عنوان مثال، برای نمایش نمونه های کد در یک صفحه به طوری که مرورگرها آنها را با نشانه گذاری واقعی اشتباه نگیرند - ما کدگذار HTML کاراکترهایی مانند براکت های زاویه را به موجودیت های محافظت شده تبدیل می کند. یک قانون سرانگشتی: فایل Markdown اصلی خود را به عنوان کپی اصلی نگه دارید و HTML را به عنوان یک صادرات یک طرفه در نظر بگیرید. اگر سند بعداً نیاز به ویرایش داشت، به جای ویرایش HTML و از دست دادن منبع تمیز، Markdown را ویرایش کرده و دوباره صادر کنید.

اشتباهات رایج و راه‌های رفع آنها

بیشتر مشکلات Markdown ناشی از چند عادت است. تازه کارها اغلب به موارد زیر برخورد می کنند:

  • بدون خط خالی در اطراف لیست‌ها: قبل از لیست یک خط خالی لازم است، در غیر این صورت پاراگراف قبلی آن را می بلعد. اگر لیست شما به صورت متن ساده ظاهر می شود، ابتدا یک خط خالی بالای آن اضافه کنید.
  • فراموش کردن فاصله بعد از هش: #Heading هیچ تیتری وجود ندارد؛ # Heading فضا ضروری است.
  • فرار از شخصیت های خاص: اگر می خواهید یک ستاره، هش یا براکت در متن شما ظاهر شود، قبل از آن یک علامت بک اسلش کنید، به عنوان مثال. \*در غیر این صورت، Markdown آن را به عنوان قالب‌بندی در نظر خواهد گرفت.
  • لینک‌های خراب: بررسی کنید که براکت‌های مربع و گرد بدون هیچ فاصله‌ای به یکدیگر متصل شده باشند و هیچ فاصله اضافی در آدرس وجود نداشته باشد.
  • لیست‌های تو در تو با تعداد زیاد: خواندن فهرست‌های تو در تو با بیش از دو یا سه سطح، چه به صورت خام و چه به صورت رندر شده، دشوار می‌شود. ساختار را ساده کنید یا بخش‌ها را بشکنید.
  • سطوح سرفصل نامنطبق: پرش از سطح یک به عنوان مستقیم به عنوان سطح سه، خوانندگان و خوانندگان صفحه را گیج می کند. سطوح را به ترتیب تنظیم کنید.
  • جدول لوله‌های نابرابر: تعداد نمادهای لوله در هر ردیف باید برابر باشد. اگر جدول به صورت یک خط طولانی ظاهر می‌شود، لوله‌های هر ردیف را بشمارید و آنها را برابر کنید.

وقتی چیزی اشتباه رندر می‌شود، پیش‌نمایش زنده بهترین ابزار تشخیصی شماست: یک چیز را تغییر دهید، پیش‌نمایش را تماشا کنید و معمولاً در عرض چند ثانیه مقصر را پیدا خواهید کرد.

وقتی Markdown ابزار مناسبی نیست

Markdown عمداً ساده است، و این سادگی محدودیت‌های خودش را دارد. این برای اسنادی که نیاز به صفحه‌آرایی دقیق دارند، مانند یک بروشور طراحی‌شده، یک رزومه با ستون‌ها و فونت‌های سفارشی یا فرمی با جداول پیچیده، مناسب نیست. این برنامه هیچ پشتیبانی داخلی برای پاورقی‌ها در هر طعمی ندارد، هیچ سرصفحه یا پاورقی ندارد و هیچ کنترل دقیقی روی رنگ‌ها، حاشیه‌ها یا اندازه فونت ندارد. یک واژه پرداز یا ابزار طراحی خاص یک انتخاب صادقانه برای این کارها است. Markdown همچنین بین نسخه‌های مختلف کمی متفاوت است - برای مثال، GitHub از جداول و لیست وظایف پشتیبانی می‌کند، در حالی که برخی از پیش‌نمایش‌دهنده‌های ساده این کار را نمی‌کنند - بنابراین اگر از یک ویژگی مدرن استفاده می‌کنید، قبل از تکیه بر آن، بررسی کنید که پلتفرم هدف شما از آن پشتیبانی می‌کند. قانون ساده این است: اگر سند شما بیشتر از کلمات، عنوان‌ها، فهرست‌ها، پیوندها و کد تشکیل شده است، Markdown به خوبی به شما خدمت خواهد کرد. اگر بیشتر مربوط به پیکربندی است، ابزار پیکربندی را انتخاب کنید.

سوالات متداول

آیا برای نوشتن Markdown باید چیزی نصب کنم؟

نه، مال ماست. ویرایشگر Markdown این ویرایشگر آنلاین رایگان کاملاً در مرورگر شما اجرا می‌شود، پیش‌نمایش زنده دارد و نیازی به ثبت‌نام ندارد.

آیا یادگیری Markdown دشوار است؟

اصول اولیه حدود ده دقیقه طول می‌کشد: عنوان‌ها، حروف پررنگ، حروف کج، فهرست‌ها و پیوندها بیشتر نوشته‌های روزمره را پوشش می‌دهند. جداول و بلوک‌های کد کمی بیشتر طول می‌کشند، اما می‌توانید آنها را در صورت نیاز یاد بگیرید.

آیا می‌توانم Markdown را به HTML تبدیل کنم؟

بله. Markdown طوری طراحی شده است که به HTML ساده تبدیل شود. در Markdown بنویسید، نتیجه را پیش‌نمایش کنید، سپس HTML رندر شده را برای استفاده در یک صفحه وب یا سیستم محتوا کپی کنید.

آیا فایل Markdown من همه جا کار خواهد کرد؟

Markdown ساده تقریباً همه جا کار می‌کند. ویژگی‌های پیشرفته بین پلتفرم‌ها متفاوت است، بنابراین اگر سند شما بین پلتفرم‌های مختلف استفاده می‌شود، به سرفصل‌ها، لیست‌ها، لینک‌ها، کد و جداول ساده پایبند باشید.
