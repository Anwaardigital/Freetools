Markdown ऑनलाइन मुफ़्त में कैसे लिखें और प्रीव्यू करें (2026 गाइड)

Markdown फ़ॉर्मेट किए हुए दस्तावेज़ लिखने का एक सादा-टेक्स्ट तरीका है। बोल्ड टेक्स्ट या हेडिंग के लिए टूलबार बटन दबाने के बजाय, आप कुछ आसान चिह्न टाइप करते हैं — हेडिंग के लिए हैश का चिह्न, बोल्ड के लिए तारांकन — और टेक्स्ट एक साफ़, फ़ॉर्मेट किए हुए पेज में बदल जाता है। इसका इस्तेमाल हर जगह होता है: GitHub पर प्रोजेक्ट README फ़ाइलें, दस्तावेज़ीकरण, निजी नोट्स, ब्लॉग ड्राफ़्ट, चैट संदेश और फ़ोरम पोस्ट। सबसे अच्छी बात यह है कि आप Markdown ऑनलाइन मुफ़्त में लिख और प्रीव्यू कर सकते हैं, बिना कुछ इंस्टॉल किए और बिना खाता बनाए। इस गाइड में आप मूल बातें सीखेंगे, शुरू से अंत तक एक पूरा दस्तावेज़ बनाएँगे, और उन आम गलतियों से बचेंगे जिनमें शुरुआती लोग फँस जाते हैं।

Markdown क्या है, और यह क्यों उपयोगी है?

Markdown को इस तरह बनाया गया था कि बदलने से पहले भी वह पढ़ने योग्य रहे। Markdown फ़ाइल सिर्फ़ टेक्स्ट होती है, इसलिए वह किसी भी एडिटर में खुलती है, किसी भी डिवाइस पर चलती है, और आपके शब्दों को कभी किसी मालिकाना फ़ॉर्मेट में बंद नहीं करती। इसकी तुलना वर्ड प्रोसेसर दस्तावेज़ से करें, जिसे खास सॉफ़्टवेयर चाहिए होता है और जिसकी फ़ॉर्मेटिंग मेनू के पीछे छिपी रहती है। Markdown के साथ, आप जो टाइप करते हैं वही आपको मिलता है, और फ़ॉर्मेटिंग चिह्न दिखाई देते और समझ में आते रहते हैं।

Markdown इन जगहों पर सबसे अच्छा काम करता है:

  • नोट्स: मीटिंग नोट्स, पढ़ाई के नोट्स और दैनिक डायरी लिखने में तेज़ और खोजने में आसान रहते हैं, क्योंकि फ़ॉर्मेटिंग में कोई रुकावट नहीं होती।
  • दस्तावेज़ीकरण: सॉफ़्टवेयर प्रोजेक्ट, यूज़र गाइड और अंदरूनी विकी आमतौर पर Markdown में लिखे जाते हैं, क्योंकि वह आसानी से वेब पेजों में बदल जाता है।
  • README फ़ाइलें: GitHub पर हर प्रोजेक्ट README.md फ़ाइल से शुरू होता है जो बताती है कि प्रोजेक्ट क्या करता है और उसका इस्तेमाल कैसे करें।
  • ब्लॉग ड्राफ़्ट: कई ब्लॉगिंग प्लेटफ़ॉर्म Markdown सीधे स्वीकार करते हैं, इसलिए आप सादे टेक्स्ट में ड्राफ़्ट लिखकर बिना दोबारा फ़ॉर्मेट किए प्रकाशित कर सकते हैं।
  • संदेश और फ़ोरम: चैट ऐप्स, समस्या ट्रैकर और चर्चा साइटें अक्सर बोल्ड, इटैलिक, लिंक और कोड के लिए Markdown का समर्थन करती हैं।

अगर आपकी लिखाई अंत में वेब पेज, README या नोट्स का सेट बनेगी, तो Markdown आमतौर पर विचार से तैयार दस्तावेज़ तक का सबसे तेज़ रास्ता है।

मूल बातें: हेडिंग, ज़ोर, सूचियाँ, लिंक, चित्र, कोड और टेबल

रोज़मर्रा की ज़्यादातर लिखाई के लिए आपको सिर्फ़ मुट्ठी भर चिह्नों की ज़रूरत है। वे ये रहे, साथ में ऐसे उदाहरण जिन्हें आप तुरंत आज़मा सकते हैं।

हेडिंग

एक से छह हैश चिह्नों का इस्तेमाल करें। एक हैश सबसे बड़ी हेडिंग है; छह सबसे छोटी है। किसी दस्तावेज़ में एक शीर्ष-स्तरीय हेडिंग होनी चाहिए, फिर उसके नीचे खंड:

# Main Title
## Section Heading
### Smaller Subheading

ज़ोर

ज़ोर के लिए टेक्स्ट को तारांकन या अंडरस्कोर में लपेटें। एक तारांकन इटैलिक देता है, दो बोल्ड देते हैं:

*italic text* इटैलिक बन जाता है, और **bold text** बोल्ड बन जाता है। बोल्ड का इस्तेमाल कम करें — मुख्य शब्दों और चेतावनियों के लिए — और इटैलिक का हल्के ज़ोर या किताबों के नामों के लिए।

सूचियाँ

बिना क्रम वाली सूचियों में हाइफ़न, तारांकन या प्लस चिह्न के बाद एक स्पेस आता है। क्रम वाली सूचियों में संख्या के बाद पूर्ण विराम आता है। आइटमों को नेस्ट करने के लिए दो स्पेस से इंडेंट करें:

- First item
- Second item
  - Nested item

1. First step
2. Second step
3. Third step

लिंक और चित्र

लिंक में दिखने वाला टेक्स्ट वर्गाकार कोष्ठकों में आता है, और उसके तुरंत बाद पता गोल कोष्ठकों में आता है। चित्र भी यही तरीका इस्तेमाल करते हैं, बस शुरुआत में विस्मयादिबोधक चिह्न लगता है:

[Visit Anwaar Digital](https://anwaardigital.com/)
![A descriptive caption](photo.jpg)

चित्रों के लिए हमेशा सार्थक विवरण लिखें। यह स्क्रीन रीडर इस्तेमाल करने वाले पाठकों की मदद करता है, और चित्र लोड न होने पर बैकअप टेक्स्ट के रूप में दिखता है।

कोड

वाक्य के अंदर छोटे स्निपेट के लिए उसे एकल बैकटिक में लपेटें, जैसे `print("hello")`। लंबे ब्लॉक के लिए कोड से पहले और बाद में अपनी-अपनी पंक्तियों पर तीन बैकटिक इस्तेमाल करें। शुरुआती बैकटिक के बाद भाषा का नाम भी लिख सकते हैं, जिसका इस्तेमाल कई प्रीव्यूअर सिंटैक्स हाइलाइटिंग के लिए करते हैं:

```python
print("Hello, Markdown!")
```

टेबल

टेबल पाइप चिह्नों और डैश की विभाजक पंक्ति से बनती हैं। उन्हें छोटा रखें — सादे टेक्स्ट में चौड़ी टेबल पढ़ना मुश्किल होता है:

| Tool | Use |
| --- | --- |
| Markdown Editor | Write and preview |
| Word Counter | Check length |

उद्धरण और क्षैतिज रेखाएँ

पंक्ति की शुरुआत में ग्रेटर-दैन चिह्न ब्लॉककोट बनाता है, जो किसी को उद्धृत करने या नोट पर ज़ोर देने के लिए उपयोगी है। अपनी पंक्ति पर तीन हाइफ़न एक क्षैतिज रेखा बनाते हैं जो खंडों को अलग करती है:

> This is a quoted line.
---

लाइव प्रीव्यू वर्कफ़्लो

Markdown को बिना देखे लिखना — चिह्न टाइप करना और उम्मीद करना कि नतीजा सही दिखे — धीमा और गलती-प्रवण है। बेहतर वर्कफ़्लो लाइव प्रीव्यू का इस्तेमाल करना है: आप एक तरफ़ टाइप करते हैं, और फ़ॉर्मेट किया हुआ नतीजा दूसरी तरफ़ तुरंत दिखता है। हमारा Markdown एडिटर ठीक इसी तरह काम करता है, पूरी तरह आपके ब्राउज़र में, बिना साइन-अप के। जैसे ही आप हेडिंग टाइप करते हैं, वह हेडिंग बन जाती है। जैसे ही आप सूची ठीक करते हैं, प्रीव्यू खुद ठीक हो जाता है। आप गलतियाँ उसी क्षण पकड़ लेते हैं जब वे होती हैं, प्रकाशित करने के बाद पता चलने के बजाय।

एक अच्छा लाइव प्रीव्यू वर्कफ़्लो इस तरह दिखता है:

  1. अपने ब्राउज़र में Markdown एडिटर खोलें।
  2. पहले अपनी संरचना का ड्राफ़्ट बनाएँ: शीर्षक, खंड हेडिंग, और हर खंड में क्या कहा जाएगा, उसके बुलेट बिंदु।
  3. हर हेडिंग के नीचे पैराग्राफ़ भरें, लिखते समय प्रीव्यू जाँचते रहें।
  4. लिंक, चित्र और कोड ब्लॉक जोड़ें, और पुष्टि करें कि हर एक प्रीव्यू में सही ढंग से दिख रहा है।
  5. प्रीव्यू को ऊपर से नीचे तक पाठक की तरह पढ़ें, लेखक की तरह नहीं। निर्यात करने से पहले जो कुछ गड़बड़ लगे, उसे ठीक करें।

क्योंकि एडिटर पूरी तरह आपके ब्राउज़र में स्थानीय रूप से चलता है, आपका ड्राफ़्ट कभी आपके डिवाइस से बाहर नहीं जाता। यह तब मायने रखता है जब आप अप्रकाशित काम, अंदरूनी दस्तावेज़ीकरण या कुछ भी गोपनीय लिख रहे हों — चिंता करने के लिए कोई सर्वर प्रति नहीं होती।

शुरू से अंत तक दस्तावेज़ लिखना: एक व्यावहारिक उदाहरण

मान लीजिए आपको एक छोटा प्रोजेक्ट README लिखना है। ढाँचे से शुरू करें, फिर उसे भरें। एक ठोस संरचना यह है: शीर्षक, एक वाक्य का सारांश, प्रोजेक्ट क्या करता है, उसे कैसे इंस्टॉल करें, उसका इस्तेमाल कैसे करें, और आगे की मदद का लिंक। Markdown में वह ढाँचा इस तरह दिखता है:

# My Project
A short description of what this project does.
## Features
- Feature one
- Feature two
## Installation
1. Download the files.
2. Open the main file.
## Learn More
[Full documentation](https://example.com/docs)

ध्यान दें कि ढाँचा किसी भी फ़ॉर्मेटिंग के बिना भी पहले से पढ़ने योग्य है। यही Markdown की मुख्य ताकत है: कच्ची फ़ाइल भी समझ में आती है। ढाँचा तैयार हो जाने पर, प्रीव्यू करते हुए एक-एक करके हर खंड का विस्तार करें। पैराग्राफ़ छोटे रखें, लंबे दस्तावेज़ों को तोड़ने के लिए हेडिंग का इस्तेमाल करें, और निर्देशों को संख्या वाली सूचियों में डालें ताकि पाठक उन्हें चरण-दर-चरण अपना सकें। दस्तावेज़ पूरा हो जाने पर, हमारे वर्ड काउंटर से शब्द गिनती या हमारे कैरेक्टर काउंटर से अक्षर गिनती जाँचें, अगर आपकी लक्षित प्लेटफ़ॉर्म की लंबाई सीमा है।

HTML निर्यात और कॉपी करना

प्रीव्यू में दस्तावेज़ सही दिखने पर, आपको आमतौर पर उसकी किसी और फ़ॉर्मेट में ज़रूरत होती है। ज़्यादातर Markdown एडिटर दो उपयोगी निर्यात देते हैं। पहला है कच्चा Markdown खुद कॉपी करना, जिसे आप GitHub, नोट लेने वाले ऐप या Markdown का समर्थन करने वाले ब्लॉगिंग प्लेटफ़ॉर्म में पेस्ट कर सकते हैं। दूसरा है रेंडर किया हुआ HTML कॉपी करना, जिसे आप कंटेंट मैनेजमेंट सिस्टम, ईमेल टेम्पलेट या वेब पेज में पेस्ट कर सकते हैं। अगर आपको कभी उस HTML का निरीक्षण करना हो या उसे सुरक्षित रूप से एनकोड करना हो — उदाहरण के लिए, कोड नमूने किसी पेज पर इस तरह दिखाने के लिए कि ब्राउज़र उन्हें असली मार्कअप न समझे — तो हमारा HTML एनकोडर कोणीय कोष्ठक जैसे अक्षरों को सुरक्षित एंटिटी में बदल देता है। एक व्यावहारिक नियम: अपनी मूल Markdown फ़ाइल को मास्टर प्रति बनाए रखें, और HTML को एकतरफ़ा निर्यात समझें। अगर बाद में दस्तावेज़ संपादित करना हो, तो Markdown संपादित करें और दोबारा निर्यात करें, बजाय HTML संपादित करने और साफ़ स्रोत खोने के।

आम गलतियाँ और उन्हें ठीक करने के तरीके

Markdown की ज़्यादातर समस्याएँ कुछ ही आदतों से आती हैं। शुरुआती लोग सबसे अक्सर इनसे टकराते हैं:

  • सूचियों के आसपास खाली पंक्तियाँ न होना: सूची से पहले एक खाली पंक्ति चाहिए, वरना पिछला पैराग्राफ़ उसे निगल जाता है। अगर आपकी सूची सादे टेक्स्ट के रूप में दिखे, तो पहले उसके ऊपर एक खाली पंक्ति जोड़ें।
  • हैश के बाद स्पेस भूलना: #Heading हेडिंग नहीं है; # Heading है। स्पेस ज़रूरी है।
  • विशेष अक्षरों से बचना: अगर आप चाहते हैं कि कोई तारांकन, हैश या कोष्ठक आपके टेक्स्ट में सचमुच दिखे, तो उसके पहले बैकस्लैश लगाएँ, जैसे \*। वरना Markdown उसे फ़ॉर्मेटिंग समझेगा।
  • टूटे हुए लिंक: जाँचें कि वर्गाकार और गोल कोष्ठक बिना किसी स्पेस के एक-दूसरे से सटे हों, और पते के अंदर कोई फालतू स्पेस न हो।
  • बहुत ज़्यादा नेस्ट की हुई सूचियाँ: दो या तीन स्तरों से ज़्यादा नेस्ट की हुई सूचियाँ कच्चे और रेंडर किए दोनों रूपों में पढ़ना मुश्किल हो जाता है। संरचना को सरल करें या खंड को बाँट दें।
  • असंगत हेडिंग स्तर: स्तर-एक हेडिंग से सीधे स्तर-तीन हेडिंग पर छलाँग पाठकों और स्क्रीन रीडरों को भ्रमित करती है। स्तरों को क्रम से पार करें।
  • असमान पाइप वाली टेबल: हर पंक्ति में पाइप चिह्नों की संख्या समान चाहिए। अगर कोई टेबल एक लंबी पंक्ति के रूप में दिखे, तो हर पंक्ति के पाइप गिनें और उन्हें बराबर करें।

जब कुछ गलत रेंडर हो, तो लाइव प्रीव्यू आपका सबसे अच्छा निदान उपकरण है: एक चीज़ बदलें, प्रीव्यू देखें, और आप आमतौर पर सेकंडों में दोषी को पकड़ लेंगे।

Markdown कब सही उपकरण नहीं है

Markdown जानबूझकर सरल है, और उस सरलता की सीमाएँ हैं। यह उन दस्तावेज़ों के लिए खराब है जिन्हें सटीक पेज लेआउट चाहिए, जैसे डिज़ाइन किया हुआ ब्रोशर, कॉलम और कस्टम फ़ॉन्ट वाला CV, या जटिल टेबलों वाला फ़ॉर्म। हर फ़्लेवर में फ़ुटनोट के लिए इसका कोई अंतर्निहित समर्थन नहीं है, कोई पेज हेडर या फ़ुटर नहीं है, और रंगों, मार्जिन या फ़ॉन्ट आकारों पर कोई बारीक नियंत्रण नहीं है। उन कामों के लिए वर्ड प्रोसेसर या समर्पित डिज़ाइन टूल ईमानदार चुनाव है। Markdown फ़्लेवरों के बीच थोड़ा भिन्न भी होता है — उदाहरण के लिए GitHub टेबल और टास्क सूचियों का समर्थन करता है, जबकि कुछ सरल प्रीव्यूअर नहीं करते — इसलिए अगर आप किसी उन्नत सुविधा का इस्तेमाल करें, तो उस पर भरोसा करने से पहले जाँच लें कि आपकी लक्षित प्लेटफ़ॉर्म उसका समर्थन करती है। सीधा नियम यह है: अगर आपका दस्तावेज़ ज़्यादातर शब्द, हेडिंग, सूचियाँ, लिंक और कोड है, तो Markdown आपकी अच्छी सेवा करेगा। अगर वह ज़्यादातर लेआउट है, तो लेआउट टूल चुनें।

अक्सर पूछे जाने वाले प्रश्न

Markdown लिखने के लिए क्या मुझे कुछ इंस्टॉल करना होगा?

नहीं। हमारे Markdown एडिटर जैसा मुफ़्त ऑनलाइन एडिटर पूरी तरह आपके ब्राउज़र में चलता है, लाइव प्रीव्यू और बिना साइन-अप के।

क्या Markdown सीखना कठिन है?

मूल बातों में लगभग दस मिनट लगते हैं: हेडिंग, बोल्ड, इटैलिक, सूचियाँ और लिंक रोज़मर्रा की ज़्यादातर लिखाई को कवर करते हैं। टेबल और कोड ब्लॉक में थोड़ा ज़्यादा समय लगता है, लेकिन आप उन्हें ज़रूरत पड़ने पर सीख सकते हैं।

क्या मैं Markdown को HTML में बदल सकता हूँ?

हाँ। Markdown को साफ़ HTML में बदलने के लिए ही बनाया गया है। Markdown में लिखें, नतीजे का प्रीव्यू करें, फिर वेब पेज या कंटेंट सिस्टम में इस्तेमाल के लिए रेंडर किया हुआ HTML कॉपी करें।

क्या मेरी Markdown फ़ाइल हर जगह काम करेगी?

बुनियादी Markdown लगभग हर जगह काम करता है। उन्नत सुविधाएँ फ़्लेवरों के बीच भिन्न होती हैं, इसलिए अगर आपका दस्तावेज़ प्लेटफ़ॉर्मों के बीच जाएगा, तो हेडिंग, सूचियाँ, लिंक, कोड और सरल टेबलों पर टिके रहें।

ऑनलाइन Markdown एडिटर इस्तेमाल करते समय क्या मेरा ड्राफ़्ट निजी रहता है?

यह एडिटर पर निर्भर करता है। हमारा Markdown एडिटर 100% स्थानीय रूप से आपके ब्राउज़र में चलता है, इसलिए आपका ड्राफ़्ट कभी आपके डिवाइस से बाहर नहीं जाता।
