CSS منی فائر

فائل سائز کم کرنے کے لیے CSS کوڈ منی فائی کریں، یا پڑھنے میں آسانی کے لیے اسے خوبصورت بنائیں۔ مفت۔

استعمال کا طریقہ

  1. CSS کوڈ ان پٹ باکس میں پیسٹ کریں — یا براہ راست .css فائل اپ لوڈ کریں۔
  2. آپشنز بدلیں: کمنٹس ہٹائیں، غیر ضروری اسپیسز حذف کریں، اور زیادہ سے زیادہ کمپریشن چاہیں تو کلر کوڈز چھوٹے کریں۔
  3. "CSS منی فائی کریں" پر کلک کریں اور آؤٹ پٹ سکڑتا دیکھیں — یہ ٹول اصل سائز بمقابلہ منی فائیڈ سائز اور بچت کا فیصد دکھاتا ہے۔
  4. منی فائیڈ CSS کاپی یا ڈاؤن لوڈ کریں، پھر اصل کی بجائے اسے HTML میں لنک کریں۔

عام سوالات

کیا یہ واقعی مفت ہے؟

جی ہاں — اس سائٹ کا ہر ٹول 100% مفت ہے، بغیر کسی حد، بغیر سائن اپ اور بغیر واٹر مارک کے۔

کیا میرا ڈیٹا محفوظ ہے؟

بالکل۔ تمام پروسیسنگ آپ کے براؤزر میں مقامی طور پر ہوتی ہے۔ آپ کی فائلیں کبھی کسی سرور پر اپ لوڈ نہیں ہوتیں۔

منی فیکیشن واقعی کیا ہٹاتی ہے؟

منی فیکیشن وہ سب ہٹاتی ہے جو براؤزر کو نہیں چاہیے: کمنٹس، اسپیسز، لائن بریکس، اضافی سیمی کولنز اور دہرائی گئی یونٹس (0px بن جاتا ہے 0)۔ یہ ہیکس کلرز بھی چھوٹے کر سکتی ہے (#ffffff بن جاتا ہے #fff) اور دہرائے گئے رولز مرج کر سکتی ہے۔ آپ کے اسٹائلز بالکل ویسے ہی دکھائے جاتے ہیں — صرف فائل چھوٹی ہوتی ہے۔

CSS فائل کتنی چھوٹی ہوگی؟

ہاتھ سے لکھی گئی CSS، جس میں کمنٹس اور فراخ فارمیٹنگ ہو، کے لیے عام طور پر 20–40%۔ بہت زیادہ کمنٹس یا فاصلے والی اسٹائل شیٹس 50% یا زیادہ سکڑ سکتی ہیں۔ یہ ٹول آپ کی درست بچت دکھاتا ہے تاکہ آپ تصدیق کر سکیں۔

کیا منی فائیڈ CSS اب بھی ایڈٹ کی جا سکتی ہے؟

تکنیکی طور پر ہاں، عملی طور پر نہیں — یہ ایک لمبی ناقابل پڑھائی لائن بن جاتی ہے۔ اصل سورس فائل ہمیشہ رکھیں اور منی فائیڈ کاپی کو بلڈ پروڈکٹ سمجھیں۔ سورس ایڈٹ کریں، دوبارہ منی فائی کریں، دوبارہ پبلش کریں۔

منی فیکیشن بمقابلہ gzip — کیا مجھے دونوں چاہئیں؟

جی ہاں، یہ دونوں جمع ہوتے ہیں۔ منی فیکیشن غیر ضروری حروف ہٹاتی ہے؛ gzip/Brotli کمپریشن (جو آپ کا سرور کرتا ہے) باقی کو کمپریس کرتا ہے۔ دونوں مل کر CSS ٹرانسفر سائز عام طور پر 70–85% کم کر دیتے ہیں۔ پہلے منی فائی کریں، پھر سرور کو کمپریس کرنے دیں۔

CSS منی فیکیشن کی مکمل گائیڈ

CSS کا ہر کلو بائٹ آپ کے پیج کی پہلی پینٹ میں تاخیر کرتا ہے — اور غیر منی فائیڈ اسٹائل شیٹس کمنٹس، انڈینٹیشن اور اسپیسز کے ساتھ بھیجی جاتی ہیں جو صرف انسانوں کے لیے ہیں۔ منی فیکیشن یہ سب سیکنڈ کے حصوں میں، مفت، بغیر کسی بصری تبدیلی کے حذف کر دیتی ہے۔ یہ گائیڈ بتاتی ہے کہ پردے کے پیچھے کیا ہوتا ہے، منی فیکیشن پرفارمنس حکمت عملی میں کیسے فٹ ہوتی ہے، اور کن غلطیوں سے بچنا ہے۔

منی فیکیشن کیا بدلتی ہے (اور کیا نہیں)

منی فیکیشن ایک محفوظ، میکانیکی تبدیلی ہے: یہ کمنٹس ہٹاتی ہے، اسپیسز مرج کرتی ہے، ہر رول بلاک میں آخری سیمی کولن حذف کرتی ہے، صفر ویلیوز سے یونٹس اتارتی ہے، کلرز چھوٹے کرتی ہے، اور ملحقہ ایک جیسے سلیکٹرز مرج کر سکتی ہے۔ یہ رولز کو کبھی اس طرح دوبارہ ترتیب نہیں دیتی کہ کیسکیڈ بدل جائے، آپ کی کلاسز کا نام کبھی نہیں بدلتی، اور ایک بھی دکھایا گیا پکسل نہیں بدلتی۔ اگر منی فائیڈ CSS براؤزر میں مختلف لگے، تو منی فائر میں خرابی ہے — یا اصل CSS کسی نازک چیز پر انحصار کرتی تھی جیسے گم شدہ سیمی کولن جسے فارمیٹنگ چھپا رہی تھی۔

ویب پرفارمنس میں منی فیکیشن کہاں فٹ ہوتی ہے

CSS رینڈرنگ کو روکتی ہے: براؤزرز مواد پینٹ نہیں کریں گے جب تک کہ وہ اسٹائل شیٹس ڈاؤن لوڈ اور پارس نہ کر لیں۔ سست موبائل کنکشن پر، 200 کلو بائٹ کی غیر منی فائیڈ اسٹائل شیٹ پورا سیکنڈ لے سکتی ہے۔ منی فیکیشن عام طور پر 20–40% بچاتی ہے، اور Brotli کمپریشن کے ساتھ کل کمی 70–85% تک پہنچ جاتی ہے۔ یہ ویب ڈویلپمنٹ میں سب سے زیادہ فائدہ والی اصلاحوں میں سے ہے کیونکہ یہ مکمل خودکار ہے — اپنی بلڈ میں ایک بار سیٹ کریں اور بھول جائیں۔ CSS پرفارمنس کے دیگر فوائد جو اس کے ساتھ جڑتے ہیں: غیر استعمال شدہ CSS ہٹانا، اباو-دی-فولڈ کریٹیکل CSS ان لائن کرنا، اور غیر اہم اسٹائل شیٹس موخر کرنا۔

منی فیکیشن بمقابلہ بیوٹیفائنگ بمقابلہ سورس میپس

آپ کے ورک فلو میں تین پروڈکٹس ہونی چاہئیں: سورس (پڑھنے کے قابل، کمنٹس کے ساتھ، اور ورژن کنٹرول میں) اورمنی فائیڈ بلڈ (جو یوزرز ڈاؤن لوڈ کرتے ہیں) اور اختیاری طور پر سورس میپ (.css.map) جو براؤزر ڈویلپر ٹولز کو منی فائیڈ فائل ڈیبگ کرتے وقت اصل سورس دکھانے دیتا ہے۔ یہ ٹول منی فائیڈ آؤٹ پٹ بناتا ہے؛ جاری پروجیکٹس کے لیے، ہر ڈپلائے پر دستی منی فائی کرنے کی بجائے منی فیکیشن کو اپنی بلڈ میں ضم کریں (Vite، webpack اور PostCSS سب ایک پلگ ان سے یہ کرتے ہیں)۔

عام غلطیاں

ہیکس اور فلٹرز: پرانے IE ہیکس سادہ منی فائرز کو الجھا سکتے ہیں — ٹارگٹ براؤزرز میں ٹیسٹ کریں۔ اہم کمنٹس: لائسنس ہیڈرز (جیسے /*! ... */) روایتی طور پر محفوظ رکھے جاتے ہیں؛ چیک کریں کہ آپ کا منی فائر انہیں رکھتا ہے اگر قانونی طور پر درکار ہوں۔ کریکٹر سیٹ: اگر CSS میں غیر ASCII حروف ہوں (مواد کی اسٹرنگز اور فونٹ نام)، تو یقینی بنائیں کہ @charset "UTF-8" کا اعلان بالکل پہلے بائٹس کے طور پر رہے۔ دو بار منی فائی نہ کریں — یہ بے ضرر تو ہے لیکن بے فائدہ، اور دوہری پروسیسنگ کبھی کبھار ایج کیسز بگاڑ دیتی ہے۔

پرائیویسی نوٹ

آپ کی اسٹائل شیٹس میں انکشاف کرنے والے کلاس نام یا غیر اعلان شدہ فیچرز کے بارے میں کمنٹس ہو سکتے ہیں۔ یہاں منی فیکیشن 100% آپ کے براؤزر میں کام کرتی ہے — آپ کا کوڈ کبھی کسی سرور کو نہیں چھوتا۔
