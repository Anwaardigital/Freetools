آن لائن مفت میں URL انکوڈ متن کیسے کریں (2026 گائیڈ)

کبھی حیران ہوئے ہیں کہ "my file.html" نامی صفحے کا لنک my%20file.html کیوں دکھاتا ہے؟ یہ URL انکوڈنگ (جسے پرسنٹ انکوڈنگ بھی کہتے ہیں) ہے: وہ طریقہ کار جو ویب ایڈریس کو خالی جگہیں، خاص کریکٹرز، اور غیر انگریزی متن محفوظ طریقے سے لے جانے دیتا ہے۔ اگر آپ لنکس بناتے ہیں، کوئری اسٹرنگز سے کام کرتے ہیں، عجیب کریکٹرز والے URLs شیئر کرتے ہیں، یا ڈی بگ کرتے ہیں کہ لنک کیوں ٹوٹتا ہے، تو آپ اس سے مسلسل ملیں گے۔ یہ گائیڈ دکھاتی ہے کہ ہمارے مفت URL انکوڈر / ڈی کوڈر سے URLs کو کیسے انکوڈ اور ڈی کوڈ کریں، بتاتی ہے کہ انکوڈنگ کب اہم ہے، اور واضح کرتی ہے کہ یہ کیا نہیں کرتا۔

URL انکوڈنگ کیا ہے؟

URLs ایک محدود کریکٹر سیٹ کے گرد ڈیزائن کیے گئے تھے۔ اس سے باہر کے کریکٹرز — خالی جگہیں، خاص معنی والے اوقاف (?، &، =)، اور غیر ASCII متن — کو محفوظ شکل میں تبدیل کرنا ضروری ہے۔ URL انکوڈنگ ہر ایسے بائٹ کو % نشان سے بدل دیتی ہے جس کے بعد دو ہیکساڈیسیمل ہندسے ہوتے ہیں جو بائٹ قدر کی نمائندگی کرتے ہیں۔ اس لیے خالی جگہ %20 بن جاتی ہے، ایمپرسینڈ %26 بن جاتا ہے، اور حرف é (UTF-8 میں دو بائٹس) %C3%A9 بن جاتا ہے۔

وہ کریکٹرز جو ہمیشہ محفوظ ہیں — حروف، اعداد، اور - _ . ~ — اچھوتے چھوڑ دیے جاتے ہیں۔ URL جزو میں باقی سب کو عام طور پر انکوڈنگ کی ضرورت ہوتی ہے۔

مرحلہ 1: URL انکوڈر / ڈی کوڈر کھولیں

کسی بھی براؤزر میں ہمارا URL انکوڈر / ڈی کوڈر کھولیں۔ بغیر سائن اپ، بغیر انسٹالیشن — صرف ان پٹ باکس، انکوڈ/ڈی کوڈ بٹن، اور آؤٹ پٹ حصہ۔

مرحلہ 2: متن کو URL محفوظ شکل میں انکوڈ کریں

  1. اپنا متن پیسٹ یا ٹائپ کریں — مثلاً، تلاش کوئری جیسے black & white photos یا خالی جگہوں والا مکمل URL۔
  2. انکوڈ کریں پر کلک کریں۔
  3. آؤٹ پٹ پرسنٹ انکوڈ شدہ نسخہ دکھاتا ہے: black%20%26%20white%20photos۔
  4. نتیجہ کاپی بٹن سے کاپی کریں۔

کوئری پیرامیٹرز والے مکمل پتے کو انکوڈ کرنے کی کوشش کریں، پھر موازنہ کریں کہ کون سے کریکٹرز بدلے اور کون سے نہیں۔ یہ موازنہ اس بات کی سمجھ بناتا ہے کہ کیا محفوظ ہے بمقابلہ کیا نہیں۔

مرحلہ 3: URL کو واپس پڑھنے والے متن میں ڈی کوڈ کریں

  1. انکوڈ شدہ URL پیسٹ کریں — جیسے https://example.com/search?q=caf%C3%A9%20menu۔
  2. ڈی کوڈ کریں پر کلک کریں۔
  3. پڑھنے والی شکل ظاہر ہوتی ہے: https://example.com/search?q=café menu۔

ڈی کوڈنگ ڈی بگ کرتے وقت واقعی مفید ہے: تجزیاتی ٹولز، سرور لاگز، اور شیئر شدہ لنکس اکثر انکوڈ شدہ شکل دکھاتے ہیں، اور ڈی کوڈنگ ظاہر کرتی ہے کہ صارف نے اصل میں کیا ٹائپ یا کلک کیا تھا۔

آپ کو اصل میں URL انکوڈنگ کب چاہیے؟

  • خاص کریکٹرز والی کوئری اسٹرنگز: & یا = والی تلاش اصطلاح بغیر انکوڈنگ کے پیرامیٹر ڈھانچہ خراب کر دے گی — انکوڈنگ ہر قدر کو برقرار رکھتی ہے۔
  • URLs میں غیر انگریزی متن: اردو، عربی، چینی، یا کسی بھی غیر لاطینی رسم الخط میں صفحہ عنوانات کو محفوظ سفر کے لیے پرسنٹ انکوڈ ہونا ضروری ہے۔
  • پروگرام کے ذریعے لنکس بنانا: جب بھی کوڈ صارف ان پٹ یا متغیرات سے URL جوڑتا ہے، ہر جزو انکوڈ ہونا چاہیے (زیادہ تر زبانوں میں بالکل اس کے لیے بلٹ ان فنکشن ہوتا ہے)۔
  • خالی جگہوں یا اوقاف والے لنکس شیئر کرنا: کچھ چیٹ ایپس اور ای میل کلائنٹس بغیر انکوڈ شدہ URLs کو بگاڑ دیتے ہیں؛ انکوڈنگ انہیں کاپی پیسٹ سے بچاتی ہے۔
  • ٹوٹے ہوئے لنکس کو ڈی بگ کرنا: خاص کریکٹرز والے URL پر 404 اکثر انکوڈنگ سے واپس آتا ہے جو دو بار ہوئی تھی — یا بالکل نہیں ہوئی تھی۔

یاد رکھنے والی عام انکوڈنگ مثالیں

  • خالی جگہ → %20 (کوئری اسٹرنگز میں آپ + بھی دیکھ سکتے ہیں، اسی چیز کے لیے پرانی کنونشن)
  • & → %26 · = → %3D · ? → %3F
  • # → %23 (اہم: بغیر انکوڈ شدہ # فریگمنٹ شروع کرتا ہے اور جو سرور وصول کرتا ہے اسے کاٹ دیتا ہے)
  • % خود → %25
  • é → %C3%A9 · ایموجی اور CJK کریکٹرز لمبی ملٹی بائٹ سیریز بن جاتے ہیں

جن غلطیوں سے بچیں

  • دوہری انکوڈنگ: پہلے سے انکوڈ شدہ اسٹرنگ کو انکوڈ کرنے سے %20 %2520 بن جاتا ہے۔ اگر آپ کے آؤٹ پٹ میں %25 سیریز دکھائی دیں تو کچھ دو بار انکوڈ ہوا تھا۔
  • پورا URL اندھا دھند انکوڈ کرنا: https:// کو انکوڈ کرنے سے : اور / کریکٹرز بگڑ جائیں گے جو URL کی ساخت بناتے ہیں۔ اجزاء کو انکوڈ کریں (پاتھ سیگمنٹس، کوئری قدریں)، پورا پتہ ایک ہی بار میں نہیں۔
  • یہ فرض کرنا کہ انکوڈنگ = سیکیورٹی: URL انکوڈنگ نقل و حمل کا طریقہ کار ہے، تحفظ نہیں۔ یہ کچھ بھی نہیں چھپاتا، خفیہ نہیں کرتا، یا صاف نہیں کرتا — انکوڈ شدہ حملہ پے لوڈ پھر بھی حملہ پے لوڈ ہے۔ اس پر کبھی سیکیورٹی کے لیے بھروسہ نہ کریں۔
  • فریگمنٹ بھولنا: # کے بعد کچھ بھی سرور تک کبھی نہیں پہنچتا، انکوڈ شدہ ہو یا نہ ہو۔

URL انکوڈنگ بمقابلہ اس کے رشتہ دار

  • URL انکوڈنگ بمقابلہ Base64: URL انکوڈنگ ویب ایڈریس کے لیے انفرادی غیر محفوظ کریکٹرز سے بچتی ہے (Base64 پورے بائنری پے لوڈز کو متن کے طور پر دوبارہ پیش کرتا ہے)۔ مختلف کام۔
  • URL انکوڈنگ بمقابلہ HTML انکوڈنگ: HTML اینٹیٹیز (HTML انکوڈر) متن کو ویب صفحے کے اندر دکھانے کے لیے محفوظ بناتی ہیں؛ URL انکوڈنگ متن کو ویب ایڈریس کے اندر سفر کرنے کے لیے محفوظ بناتی ہے۔ دونوں سیاق و سباق میں رکھی گئی اسٹرنگ کو دونوں کی ضرورت ہو سکتی ہے، درست ترتیب میں لاگو کی گئی۔
  • URL انکوڈنگ بمقابلہ ہیشنگ: انکوڈنگ مکمل طور پر الٹی جا سکتی ہے؛ ہیشنگ یک طرفہ ہے۔ دونوں کو کبھی الجھائیں نہیں۔

عمومی سوالات

کیا URL انکوڈر نجی ہے؟

جی ہاں — تمام انکوڈنگ اور ڈی کوڈنگ آپ کے براؤزر میں مقامی طور پر ہوتی ہے۔ جو کچھ آپ پیسٹ کرتے ہیں وہ کہیں اپ لوڈ نہیں ہوتا۔

کچھ URLs خالی جگہوں کے لیے %20 کے بجائے + کیوں دکھاتے ہیں؟

HTML فارم جمع کرانے میں (application/x-www-form-urlencoded فارمیٹ)، خالی جگہوں کو روایتی طور پر + لکھا جاتا ہے۔ URLs میں کہیں اور، %20 معیار ہے۔ دونوں اپنے اپنے سیاق و سباق میں خالی جگہ میں ڈی کوڈ ہوتے ہیں۔

کیا میں پورا URL ایک ہی بار میں انکوڈ کر سکتا ہوں؟

آپ کر سکتے ہیں، لیکن عام طور پر نہیں کرنا چاہیے — یہ ساختی کریکٹرز (:، /، ?) کو بھی انکوڈ کر دے گا۔ صرف غیر محفوظ کریکٹرز والے حصے انکوڈ کریں۔

کیا URL انکوڈنگ غیر انگریزی متن کے لیے کام کرتی ہے؟

جی ہاں۔ کریکٹرز پہلے UTF-8 بائٹس میں تبدیل ہوتے ہیں، پھر ہر بائٹ پرسنٹ انکوڈ ہوتا ہے — اس لیے اردو، عربی، ایموجی، اور باقی سب درست واپس آتے ہیں۔
