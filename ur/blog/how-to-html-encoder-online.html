آن لائن مفت HTML اینٹیٹیز کیسے انکوڈ کریں (2026 گائیڈ)

<div>Hello</div> کو بلاگ پوسٹ میں پیسٹ کرنے کی کوشش کریں اور آپ کو مسئلہ نظر آئے گا: براؤزر <div> کو ٹیکسٹ کے طور پر دکھانے کے بجائے اصل HTML ٹیگ سمجھتا ہے۔ حل HTML انکوڈنگ ہے — خاص کریکٹرز کو &lt; جیسی اینٹیٹیز میں تبدیل کرنا جنہیں براؤزرز لفظی طور پر دکھاتے ہیں۔ بلاگرز، CMS صارفین، ای میل ٹیمپلیٹ بنانے والے، اور ڈویلپرز کو اس کی مسلسل ضرورت ہوتی ہے۔ یہ گائیڈ آپ کو دکھاتی ہے کہ ہمارے مفت HTML انکوڈر سے HTML اینٹیٹیز کو کیسے انکوڈ اور ڈی کوڈ کریں، ایک آسان ریفرنس ٹیبل دیتی ہے، اور انکوڈنگ کی ایماندارانہ سیکیورٹی حدود بتاتی ہے۔

HTML اینٹیٹیز کیا ہیں؟

HTML اینٹیٹی ایک ٹیکسٹ سیکوئنس ہے جو ایک کریکٹر کی نمائندگی کرتی ہے، &name; (نام والی) یا &#number; (عددی) کے طور پر لکھی جاتی ہے۔ جب براؤزر صفحے کے سورس میں &lt; دیکھتا ہے، تو یہ ٹیگ شروع کرنے کے بجائے لفظی < کریکٹر رینڈر کرتا ہے۔ پانچ کریکٹرز جو سب سے زیادہ اہم ہیں: < → &lt; (کم تر — ورنہ ٹیگ شروع کر دے گا)؛ > → &gt; (زیادہ تر — ورنہ ٹیگ ختم کر دے گا)؛ & → &amp; (ایمپرسینڈ — ورنہ اینٹیٹی شروع کر دے گا)؛ " → &quot; (ڈبل کوٹ — ورنہ ایٹریبیوٹ ویلیو ختم کر دے گا)؛ ' → &#39; (سنگل کوٹ — سنگل کوٹڈ ایٹریبیوٹس میں وہی تشویش)۔ ایمپرسینڈ کو پہلے انکوڈ کریں (یا ٹول کو ترتیب سنبھالنے دیں) — ورنہ آپ ان اینٹیٹیز کو ڈبل انکوڈ کر دیں گے جو آپ نے ابھی بنائی ہیں۔

مرحلہ 1: HTML انکوڈر کھولیں

کسی بھی براؤزر میں ہمارا HTML انکوڈر کھولیں۔ بغیر رجسٹریشن، بغیر انسٹالیشن۔ آپ کو ان پٹ حصہ، انکوڈ/ڈی کوڈ بٹنز، اور آؤٹ پٹ حصہ نظر آئے گا۔

مرحلہ 2: اپنا کوڈ یا ٹیکسٹ انکوڈ کریں

وہ اسنیپٹ پیسٹ کریں جسے آپ دکھانا چاہتے ہیں — مثلاً: <p class="note">Tom & Jerry</p>۔ Encode پر کلک کریں۔ آؤٹ پٹ اینٹیٹی انکوڈ شدہ ورژن دکھاتا ہے، جو کسی بھی HTML صفحے، بلاگ ایڈیٹر، یا CMS میں پیسٹ کرنے کے لیے محفوظ ہے جو خام HTML قبول کرتا ہے۔ کاپی بٹن سے نتیجہ کاپی کریں۔ جب آپ انکوڈ شدہ اسنیپٹ والا صفحہ دیکھتے ہیں، تو وزٹرز کو کوڈ بالکل ویسا ہی نظر آتا ہے جیسا آپ نے لکھا تھا — ٹیگز، کوٹس، اور سب کچھ — براؤزر کے اسے رینڈر کرنے کی کوشش کرنے کے بجائے۔

مرحلہ 3: اینٹیٹیز کو واپس کریکٹرز میں ڈی کوڈ کریں

اینٹیٹی انکوڈ شدہ ٹیکسٹ پیسٹ کریں (جیسے کسی صفحے کے سورس ویو سے کاپی کیا ہوا)۔ Decode پر کلک کریں۔ اصل کریکٹرز بحال ہو جاتے ہیں۔ ڈی کوڈنگ اس وقت مفید ہے جب آپ کو انکوڈ شدہ مواد ورثے میں ملا ہو — ڈیٹا بیس ایکسپورٹ، پرانے CMS، یا اسکریپ شدہ HTML سے — اور آپ کو صاف اصل واپس چاہیے ہو۔

آپ کو HTML انکوڈنگ کی کب ضرورت ہوتی ہے؟

  • مضامین میں کوڈ اسنیپٹس: HTML دکھانے والے ٹیوٹوریلز، یا یہاں تک کہ < > & پر مشتمل ٹیکسٹ، انکوڈنگ کے بغیر ٹوٹ جاتا ہے۔
  • CMS اور بلاگ مواد: WordPress طرز کے ایڈیٹرز یا اسٹیٹک سائٹ مارک ڈاؤن میں کوڈ پیسٹ کرنے کے لیے اکثر رینڈرنگ سے بچنے کے لیے انکوڈ شدہ اینٹیٹیز چاہیے ہوتی ہیں۔
  • ای میل ٹیمپلیٹس: لفظی کوڈ سیمپلز یا خاص کریکٹرز والی HTML ای میلز کو تمام میل کلائنٹس میں مستقل دکھانے کے لیے اینٹیٹیز چاہیے ہوتی ہیں۔
  • صارف کا ان پٹ دکھانا: صارف کے ٹائپ کردہ ٹیکسٹ (تبصرے، فارم پری ویوز) کو انکوڈ کیے بغیر دکھانے سے ان کا <script> آپ کے صفحے کا اسکرپٹ بن جاتا ہے — کلاسک اسٹورڈ XSS سیٹ اپ۔
  • ایٹریبیوٹ ویلیوز: ایٹریبیوٹ ویلیوز کے اندر کوٹس انکوڈ ہونے چاہییں ورنہ ایٹریبیوٹ (اور ممکنہ طور پر مارک اپ) ٹوٹ جاتا ہے۔

فوری اینٹیٹی ریفرنس ٹیبل

&lt; — < · &gt; — > · &amp; — & · &quot; — " · &#39; — ' · &nbsp; — نان بریکنگ اسپیس · &copy; — © · &reg; — ® · &trade; — ™ · &ndash; — – · &mdash; — — · &hellip; — … · &euro; — € · &pound; — £ · &deg; — °۔ نام والی اینٹیٹیز عام صورتوں کا احاطہ کرتی ہیں؛ عددی اینٹیٹیز (< کے لیے &#60;، مثلاً) کسی بھی یونیکوڈ کریکٹر کی نمائندگی کر سکتی ہیں۔

ایماندارانہ سیکیورٹی تصویر

صارف کا مواد دکھانے سے پہلے اسے HTML انکوڈ کرنا کراس سائٹ اسکرپٹنگ (XSS) کے خلاف ایک حقیقی، اہم دفاع ہے — اسی طرح تبصرے تبصرے ہی رہتے ہیں، قابل عمل کوڈ بننے کے بجائے۔ لیکن حدود سیدھی رکھیں: انکوڈنگ سیاق و سباق پر منحصر ہے۔ HTML انکوڈنگ HTML باڈی مواد میں رکھے گئے ٹیکسٹ کی حفاظت کرتی ہے۔ یہ اسی اسٹرنگ کو <script> بلاک، CSS سیاق، یا URL کے اندر محفوظ نہیں بناتی — ہر سیاق کو اپنی انکوڈنگ چاہیے ہوتی ہے (URLs کے لیے URL انکوڈنگ، مثلاً)۔ انکوڈنگ ایک پرت ہے، مکمل حکمت عملی نہیں۔ سنجیدہ ایپلی کیشنز آؤٹ پٹ انکوڈنگ کو ان پٹ ویلیڈیشن، Content-Security-Policy ہیڈرز (ہمارا سیکیورٹی ہیڈرز چیکر دیکھیں)، اور فریم ورک کی فراہم کردہ آٹو ایسکیپنگ کے ساتھ ملاتی ہیں۔ انکوڈنگ ≠ انکرپشن یا چھپانا۔ اینٹیٹیز آسانی سے الٹی جا سکتی ہیں — انہیں راز چھپانے کے لیے استعمال نہ کریں۔

بچنے والی غلطیاں

  • ڈبل انکوڈنگ: &lt; کو دوبارہ انکوڈ کرنے سے &amp;lt; بنتا ہے، جو "<" کے بجائے لفظی طور پر "&lt;" کے طور پر دکھائی دیتا ہے۔ اگر آپ کے صفحے میں اینٹیٹی نام ٹیکسٹ کے طور پر نظر آتے ہیں، تو کچھ دو بار انکوڈ ہوا تھا۔
  • ایمپرسینڈ کو آخر میں انکوڈ کرنا: ہمیشہ & کو پہلے انکوڈ کریں (ٹولز یہ خود بخود کرتے ہیں)؛ اسے آخر میں کرنے سے وہ اینٹیٹیز خراب ہو جاتی ہیں جو آپ نے ابھی بنائی ہیں۔
  • ایٹریبیوٹس میں کوٹس بھول جانا: < اور > کو ساری توجہ ملتی ہے، لیکن ایٹریبیوٹ ویلیو کے اندر غیر انکوڈ شدہ کوٹ وہی ہے جو مارک اپ توڑتا ہے — اور انجیکشن کو ممکن بناتا ہے۔

اکثر پوچھے جانے والے سوالات

کیا HTML انکوڈر نجی ہے؟

جی ہاں — انکوڈنگ اور ڈی کوڈنگ مکمل طور پر آپ کے براؤزر میں چلتی ہیں۔ جو آپ پیسٹ کرتے ہیں وہ کہیں اپ لوڈ نہیں ہوتا۔

نام والی اور عددی اینٹیٹیز میں کیا فرق ہے؟

نام والی اینٹیٹیز (&lt;) عام کریکٹرز کے لیے پڑھنے کے قابل یادداشتیں ہیں؛ عددی اینٹیٹیز (&#60; یا &#x3C;) کریکٹرز کو یونیکوڈ کوڈ پوائنٹ سے ایڈریس کرتی ہیں اور کسی بھی چیز کی نمائندگی کر سکتی ہیں۔ براؤزرز ان کے ساتھ ایک جیسا سلوک کرتے ہیں۔

اگر میرا فریم ورک خود بخود ایسکیپ کرتا ہے تو کیا مجھے اب بھی انکوڈنگ چاہیے؟

جدید فریم ورکس (React، Vue، Django ٹیمپلیٹس) زیادہ تر سیاقوں میں بطور ڈیفالٹ ایسکیپ کرتے ہیں — جو بہت اچھا ہے۔ آپ کو خام HTML داخل کرنے کے مقامات، ای میل ٹیمپلیٹس، اسٹیٹک مواد، اور کہیں بھی جہاں آپ فریم ورک کی ایسکیپنگ کو بائی پاس کرتے ہیں، کے لیے دستی انکوڈنگ اب بھی چاہیے ہوتی ہے۔

کیا انکوڈ شدہ ٹیکسٹ میں وائرس یا ہیک ہو سکتا ہے؟

انکوڈ شدہ ٹیکسٹ غیر فعال ہے — یہ صرف کریکٹرز ہیں۔ خطرہ ہمیشہ غیر انکوڈ شدہ ورژن کے کوڈ کے طور پر سمجھے جانے میں تھا۔ انکوڈنگ بالکل اسی کو روکتی ہے۔
