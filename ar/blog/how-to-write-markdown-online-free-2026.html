كيفية كتابة Markdown ومعاينتها عبر الإنترنت مجانًا (دليل 2026)

Markdown طريقة لكتابة المستندات المنسّقة بنص عادي. فبدلًا من النقر على أزرار شريط الأدوات للحصول على نص عريض أو عنوان، تكتب بضع رموز بسيطة — علامة المربع للعنوان، ونجمات للنص العريض — ويُحوَّل النص إلى صفحة نظيفة ومنسّقة. وهي تُستخدم في كل مكان: ملفات README للمشاريع على GitHub، والتوثيق، والملاحظات الشخصية، ومسودات المدونات، ورسائل الدردشة، ومنشورات المنتديات. وأفضل ما فيها أنك تستطيع كتابة Markdown ومعاينتها عبر الإنترنت مجانًا، دون تثبيت أي شيء ودون إنشاء حساب. في هذا الدليل، ستتعلّم الأساسيات، وستبني مستندًا كاملًا من البداية إلى النهاية، وستتجنّب الأخطاء الشائعة التي يقع فيها المبتدئون.

ما هو Markdown، ولماذا هو مفيد؟

صُمم Markdown ليكون مقروءًا حتى قبل تحويله. فملف Markdown مجرد نص، لذلك يفتح في أي محرر، ويعمل على أي جهاز، ولا يحبس كلماتك أبدًا داخل صيغة خاصة. قارن ذلك بمستند معالج الكلمات، الذي يحتاج إلى برنامج محدد ويخفي تنسيقه خلف القوائم. مع Markdown، ما تكتبه هو ما تحصل عليه، وتبقى رموز التنسيق ظاهرة ومفهومة.

إليك المجالات التي يتألق فيها Markdown:

  • الملاحظات: ملاحظات الاجتماعات وملاحظات الدراسة واليوميات تبقى سريعة الكتابة وسهلة البحث، لأنه لا يوجد احتكاك في التنسيق.
  • التوثيق: مشاريع البرمجيات وأدلة المستخدم ومواقع الويكي الداخلية تُكتب عادةً بـ Markdown، لأنه يتحول بدقة إلى صفحات ويب.
  • ملفات README: كل مشروع على GitHub يبدأ بملف README.md يشرح ما يفعله المشروع وكيفية استخدامه.
  • مسودات المدونات: كثير من منصات التدوين تقبل Markdown مباشرة، فيمكنك كتابة المسودة بنص عادي ونشرها دون إعادة تنسيق.
  • الرسائل والمنتديات: تطبيقات الدردشة ومتتبعات المشكلات ومواقع النقاش تدعم غالبًا Markdown للنص العريض والمائل والروابط والأكواد.

إذا كانت كتابتك ستنتهي صفحة ويب أو ملف README أو مجموعة ملاحظات، فإن Markdown عادةً هو أسرع طريق من الفكرة إلى المستند النهائي.

الأساسيات: العناوين، والتأكيد، والقوائم، والروابط، والصور، والأكواد، والجداول

لا تحتاج إلا إلى حفنة من الرموز لتغطية معظم الكتابة اليومية. إليك هذه الرموز، مع أمثلة يمكنك تجربتها فورًا.

العناوين

استخدم من علامة مربع واحدة إلى ست علامات. علامة واحدة هي أكبر عنوان؛ وست علامات هي أصغر عنوان. ويجب أن يحتوي المستند على عنوان واحد من المستوى الأعلى، ثم أقسام تحته:

# Main Title
## Section Heading
### Smaller Subheading

التأكيد

غلّف النص بنجمات أو شرطات سفلية للتأكيد. نجمة واحدة تعطي نصًا مائلًا، ونجمتان تعطيان نصًا عريضًا:

*italic text* يصبح نصًا مائلًا، و**bold text** يصبح نصًا عريضًا. استخدم العريض باعتدال — للمصطلحات الأساسية والتحذيرات — والمائل للتأكيد الخفيف أو عناوين الكتب.

القوائم

القوائم غير المرتبة تستخدم شرطة أو نجمة أو علامة زائد، متبوعة بمسافة. والقوائم المرتبة تستخدم أرقامًا متبوعة بنقطة. أزح العناصر بمسافتين لتداخلها:

- First item
- Second item
  - Nested item

1. First step
2. Second step
3. Third step

الروابط والصور

الروابط تضع النص الظاهر بين قوسين معقوفين، يتبعه مباشرة العنوان بين قوسين مستديرين. والصور تستخدم النمط نفسه مع علامة تعجب في البداية:

[Visit Anwaar Digital](https://anwaardigital.com/)
![A descriptive caption](photo.jpg)

اكتب دائمًا وصفًا ذا معنى للصور. فهو يساعد القراء الذين يستخدمون قارئات الشاشة، ويظهر كنص بديل إذا فشل تحميل الصورة.

الأكواد

لمقتطف قصير داخل جملة، غلّفه بعلامة اقتباس خلفية واحدة، مثل `print("hello")`. أما الكتلة الأطول، فاستخدم ثلاث علامات اقتباس خلفية في أسطر مستقلة قبل الكود وبعده. ويمكنك أيضًا تسمية اللغة بعد علامات الاقتباس الخلفية الافتتاحية، وهو ما تستخدمه كثير من أدوات المعاينة للتلوين النحوي:

```python
print("Hello, Markdown!")
```

الجداول

تُبنى الجداول بأحرف الأنابيب وصف فاصل من الشرطات. اجعلها قصيرة — فالجداول العريضة يصعب قراءتها في النص العادي:

| Tool | Use |
| --- | --- |
| Markdown Editor | Write and preview |
| Word Counter | Check length |

الاقتباسات والقواعد الأفقية

علامة أكبر من في بداية السطر تنشئ اقتباسًا، وهو مفيد لاقتباس شخص ما أو إبراز ملاحظة. وثلاث شرطات في سطر مستقل تنشئ قاعدة أفقية تفصل بين الأقسام:

> This is a quoted line.
---

سير عمل المعاينة المباشرة

كتابة Markdown دون رؤية النتيجة — كتابة الرموز والأمل بأن تبدو النتيجة صحيحة — بطيئة وعرضة للأخطاء. وسير العمل الأفضل هو استخدام معاينة مباشرة: تكتب في جهة، وتظهر النتيجة المنسّقة في الجهة الأخرى فورًا. يعمل محرر Markdown لدينا بهذه الطريقة بالضبط، بالكامل في متصفحك، دون تسجيل. فعندما تكتب عنوانًا، يصبح عنوانًا. وعندما تصلح قائمة، تصلح المعاينة نفسها. وتكتشف الأخطاء لحظة ارتكابها، بدلًا من اكتشافها بعد النشر.

يبدو سير عمل المعاينة المباشرة الجيد هكذا:

  1. افتح محرر Markdown في متصفحك.
  2. صُغ البنية أولًا: العنوان، وعناوين الأقسام، والنقاط التي سيتناولها كل قسم.
  3. املأ الفقرات تحت كل عنوان، مع مراجعة المعاينة أثناء الكتابة.
  4. أضف الروابط والصور وكتل الأكواد، وتأكد من أن كل واحد منها يظهر بشكل صحيح في المعاينة.
  5. اقرأ المعاينة من الأعلى إلى الأسفل كما يقرأها القارئ، لا كما كتبها الكاتب. أصلح أي شيء يبدو غير سليم قبل التصدير.

ولأن المحرر يعمل محليًا في متصفحك، فإن مسودتك لا تغادر جهازك أبدًا. وهذا مهم إذا كنت تصوغ عملًا غير منشور أو توثيقًا داخليًا أو أي شيء سري — فلا توجد نسخة على خادم تقلق بشأنها.

كتابة مستند من البداية إلى النهاية: مثال عملي

افترض أنك تحتاج إلى كتابة ملف README قصير لمشروع. ابدأ بالهيكل، ثم املأه. والبنية الجيدة هي: العنوان، وجملة ملخص واحدة، وما يفعله المشروع، وكيفية تثبيته، وكيفية استخدامه، ورابط لمزيد من المساعدة. في Markdown، يبدو ذلك الهيكل هكذا:

# My Project
A short description of what this project does.
## Features
- Feature one
- Feature two
## Installation
1. Download the files.
2. Open the main file.
## Learn More
[Full documentation](https://example.com/docs)

لاحظ كيف أن الهيكل مفهوم أصلًا قبل تطبيق أي تنسيق. تلك هي قوة Markdown الأساسية: فحتى الملف الخام مفهوم. وبمجرد وضع الهيكل، وسّع كل قسم على حدة، مع المعاينة أثناء الكتابة. اجعل الفقرات قصيرة، واستخدم العناوين لتقسيم المستندات الطويلة، وضع التعليمات في قوائم مرقمة ليتمكن القراء من متابعتها خطوة بخطوة. وعندما ينتهي المستند، تحقق من عدد الكلمات باستخدام عدّاد الكلمات لدينا أو عدد الأحرف باستخدام عدّاد الأحرف إذا كانت المنصة المستهدفة لها حد للطول.

تصدير HTML ونسخه

عندما يبدو مستندك صحيحًا في المعاينة، ستحتاج عادةً إليه بصيغة أخرى. وتقدم معظم محررات Markdown تصديرين مفيدين. الأول هو نسخ Markdown الخام نفسه، الذي يمكنك لصقه في GitHub أو تطبيق ملاحظات أو منصة تدوين تدعم Markdown. والثاني هو نسخ HTML المعروض، الذي يمكنك لصقه في نظام إدارة محتوى أو قالب بريد إلكتروني أو صفحة ويب. وإذا احتجت يومًا إلى فحص ذلك HTML أو ترميزه بأمان — مثلًا لعرض عينات أكواد على صفحة دون أن يفسّرها المتصفح كترميز حقيقي — فإن مرمّز HTML لدينا يحوّل أحرفًا مثل الأقواس الزاوية إلى كيانات آمنة. والقاعدة العملية: احتفظ بملف Markdown الأصلي نسخة رئيسية، وتعامل مع HTML كتصدير أحادي الاتجاه. فإذا احتجت لاحقًا إلى تعديل المستند، عدّل Markdown وصدّره من جديد، بدلًا من تعديل HTML وفقدان المصدر النظيف.

الأخطاء الشائعة وكيفية إصلاحها

معظم مشكلات Markdown تأتي من مجموعة صغيرة من العادات. إليك أكثر ما يصادفه المبتدئون:

  • غياب الأسطر الفارغة حول القوائم: القائمة تحتاج إلى سطر فارغ قبلها، وإلا ابتلعتها الفقرة السابقة. فإذا ظهرت قائمتك كنص عادي، أضف سطرًا فارغًا فوقها أولًا.
  • نسيان المسافة بعد علامة المربع: #Heading ليس عنوانًا؛ أما # Heading فهو عنوان. فالمسافة مطلوبة.
  • تهريب الأحرف الخاصة: إذا أردت أن يظهر نجم أو مربع أو قوس حرفيًا في نصك، ضع شرطة مائلة خلفية قبله، مثل \*. وإلا سيعامله Markdown كتنسيق.
  • الروابط المعطلة: تأكد من أن القوسين المعقوفين والمستديرين متجاوران دون مسافة بينهما، وأن العنوان لا يحتوي على مسافات شاردة داخله.
  • التداخل المفرط للقوائم: القوائم المتداخلة أكثر من مستويين أو ثلاثة تصبح صعبة القراءة بصيغتها الخام والمعروضة. بسّط البنية أو قسّم القسم بدلًا من ذلك.
  • مستويات العناوين غير المتسقة: القفز من عنوان من المستوى الأول مباشرة إلى عنوان من المستوى الثالث يربك القراء وقارئات الشاشة. تنقّل عبر المستويات بالترتيب.
  • الجداول ذات الأنابيب غير المتساوية: كل صف يحتاج إلى العدد نفسه من أحرف الأنابيب. فإذا ظهر الجدول سطرًا واحدًا طويلًا، عُدّ الأنابيب في كل صف وساوِ بينها.

عندما يظهر شيء بشكل خاطئ، تكون المعاينة المباشرة أفضل أداة تشخيص لديك: غيّر شيئًا واحدًا، وراقب المعاينة، وستكتشف الجاني عادةً في ثوانٍ.

متى لا يكون Markdown الأداة المناسبة

Markdown بسيط عن قصد، وهذه البساطة لها حدود. فهو خيار ضعيف للمستندات التي تحتاج إلى تخطيط دقيق للصفحة، مثل كتيّب مصمم، أو سيرة ذاتية بأعمدة وخطوط مخصصة، أو نموذج بجداول معقدة. وليس له دعم مدمج للحواشي السفلية في كل نكهة، ولا رؤوس أو تذييلات للصفحات، ولا تحكم دقيق في الألوان أو الهوامش أو أحجام الخطوط. لتلك المهام، يكون معالج الكلمات أو أداة تصميم مخصصة هو الخيار الصادق. كما أن Markdown يختلف قليلًا بين النكهات — فـ GitHub مثلًا يدعم الجداول وقوائم المهام، بينما بعض أدوات المعاينة الأبسط لا تدعمها — لذا إذا استخدمت ميزة متقدمة، تحقق من أن منصتك المستهدفة تدعمها قبل الاعتماد عليها. والقاعدة العامة بسيطة: إذا كان مستندك معظمه كلمات وعناوين وقوائم وروابط وأكواد، فسيخدمك Markdown جيدًا. أما إذا كان معظمه تخطيطًا، فاختر أداة تخطيط بدلًا منه.

الأسئلة الشائعة

هل أحتاج إلى تثبيت أي شيء لكتابة Markdown؟

لا. فمحرر مجاني عبر الإنترنت مثل محرر Markdown لدينا يعمل بالكامل في متصفحك، مع معاينة مباشرة ودون تسجيل.

هل تعلّم Markdown صعب؟

الأساسيات تستغرق نحو عشر دقائق: العناوين والعريض والمائل والقوائم والروابط تغطي معظم الكتابة اليومية. والجداول وكتل الأكواد تستغرق وقتًا أطول قليلًا، لكن يمكنك تعلمها عند الحاجة إليها.

هل يمكنني تحويل Markdown إلى HTML؟

نعم. فـ Markdown مصمم ليتحول إلى HTML نظيف. اكتب بـ Markdown، وعاين النتيجة، ثم انسخ HTML المعروض لاستخدامه في صفحة ويب أو نظام محتوى.

هل سيعمل ملف Markdown الخاص بي في كل مكان؟

Markdown الأساسي يعمل في كل مكان تقريبًا. والميزات المتقدمة تختلف بين النكهات، لذا التزم بالعناوين والقوائم والروابط والأكواد والجداول البسيطة إذا كان مستندك سينتقل بين المنصات.

هل مسودتي خاصة عندما أستخدم محرر Markdown عبر الإنترنت؟

يعتمد ذلك على المحرر. فـ محرر Markdown لدينا يعمل محليًا بنسبة 100% في متصفحك، لذلك لا تغادر مسودتك جهازك أبدًا.
